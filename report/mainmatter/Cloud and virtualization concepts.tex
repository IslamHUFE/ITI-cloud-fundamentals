\chapter{Cloud and virtualization concepts}

\section{Introduction}
Virtualization is an attempt to trick the operating system into believing it is running directly on its own across the entire hardware of the device, while another operating system runs alongside it, also tricked. Virtualization is used in servers and workstations to run multiple operating systems on the same machine and connect them to each other via virtual networks (Software-Defined Networks) Figure[\ref{fig:virtualisation1}].

\begin{figure}
	\centering
	\includegraphics[width=0.7\linewidth]{figures/virtualisation1}
	\caption{virtualisation}
	\label{fig:virtualisation1}
\end{figure}

\section{Why we need virtualization}

\begin{itemize}
	\item Modern computing is more efficient due to virtualization
	\item Virtualization can be used for mobile, personal and cloud computing
	\item Virtualization enables computers to be more efficient in a similar fashion
	\item Computers that use virtualization optimize the available compute resources
\end{itemize}

\section{What is a Virtual Machine}
\begin{minipage}[c]{0.6\textwidth}
	A \textbf{VM (Virtual Machine)} is a software-based computer that behaves like a physical one. Virtualization creates \textbf{virtual hardware} by cloning the physical hardware, and the \textbf{hypervisor} uses this virtual hardware to build the VM.
	
	A VM is simply a \textbf{set of files}, so it can be exported and moved to other hosts, and it can run applications like a physical machine. With a hypervisor running VMs, one computer can run \textbf{multiple operating systems simultaneously} (unlike dual boot, where only one OS runs at a time).
\end{minipage}%

\section{The Hypervisor}

\begin{minipage}[c]{0.6\textwidth}
	The hypervisor is a \textbf{software layer} that sits between the hardware and the operating systems. It pulls the physical resources (CPU, RAM, storage, network) from the server, turns them into virtual hardware, and shares them among the VMs it hosts.
\end{minipage}%
\hfill
\begin{minipage}[r]{0.40\textwidth}
	
	\begin{figure}[H]
		\centering
		\includegraphics[width=0.8\linewidth]{figures/Hypervisor}
		\caption{Hypervisor layer}
		\label{Hypervisor}
	\end{figure}
\end{minipage}

\subsection{Types of Hypervisors}

\begin{minipage}[c]{0.6\textwidth}
	\subsubsection{Type 1 (Bare-metal)}
	Installed \textbf{directly on the hardware} without a host OS, so it is faster and used in data centers.
	
	\textbf{Examples:} VMware ESXi, Microsoft Hyper-V, Citrix XenServer.
\end{minipage}%
\hfill
\begin{minipage}[r]{0.40\textwidth}
	
	\begin{figure}[H]
		\centering
		\includegraphics[width=0.8\linewidth]{figures/Type1}
		\caption{Type 1 hypervisor}
		\label{Type1}
	\end{figure}
\end{minipage}

\begin{minipage}[c]{0.6\textwidth}
	\subsubsection{Type 2 (Hosted)}
	Installed as an application \textbf{on top of a host operating system}, so it is easier to set up and used on personal computers.
	
	\textbf{Examples:} VMware Workstation, VirtualBox, QEMU, KVM.
\end{minipage}%
\hfill
\begin{minipage}[r]{0.40\textwidth}
	
	\begin{figure}[H]

\subsection{Practice: Creating a VM on VMware Workstation}
\begin{enumerate}
	\item Install VMware Workstation, open it, and choose \textbf{Create a New Virtual Machine} (or press \texttt{Ctrl+N}).
	\item Select the installation source (for example a Windows 10 ISO file).
	\item Set the VM name, the number of processors, the RAM, and the disk size.
	\item Finish the wizard, power on the VM, and it will boot from the ISO to start the OS installation.
\end{enumerate}

\section{The Data Center}

\begin{minipage}[c]{0.6\textwidth}
	A data center is the \textbf{hardware infrastructure} that supports virtualization, focused on processing large amounts of data. It has three main components:
	\begin{itemize}
		\item \textbf{Compute}
		\item \textbf{Storage}
		\item \textbf{Networks}
	\end{itemize}
\end{minipage}%
\hfill
\begin{minipage}[r]{0.40\textwidth}
	
	\begin{figure}[H]
		\centering
		\includegraphics[width=0.9\linewidth]{figures/DataCenter}
		\caption{Data center}
		\label{DataCenter}
	\end{figure}
\end{minipage}

\begin{minipage}[c]{0.6\textwidth}
	\subsection{Compute Systems}
	The hardware and operating system software that runs the applications. A PC has a user-friendly interface, while a server focuses on running programs.
	
	\textbf{Types of servers:} Tower, Rack-mounted, and Blade server.
	
	Data centers typically use the \textbf{x86} architecture (the type of processor used by the server). Virtualization technology is compatible with \textbf{64-bit} but not 32-bit.
\end{minipage}%
\hfill
\begin{minipage}[r]{0.40\textwidth}
	
	\begin{figure}[H]
		\centering
		\includegraphics[width=0.9\linewidth]{figures/Servers}
		\caption{Types of servers}
		\label{Servers}
	\end{figure}
\end{minipage}

\subsection{Networks}
Transfer data across the data center so that devices can communicate. They use switches, NICs, routers, and Ethernet cables (see Chapter 1).

\begin{minipage}[c]{0.6\textwidth}
	\subsection{Storage}
	A data center must accommodate high levels of data, so it uses devices built specifically for storage that provide \textbf{availability} and \textbf{redundancy}.
	
	\subsubsection{RAID}
	\textbf{Redundant Array of Independent Disks:} hard drives linked together to create a large volume of redundant storage. The RAID level defines the writing method:
	\begin{itemize}
		\item \textbf{RAID 0:} Striping.
		\item \textbf{RAID 1:} Mirroring.
		\item \textbf{RAID 5:} Parity.
	\end{itemize}
\end{minipage}%
\hfill
\begin{minipage}[r]{0.40\textwidth}
	
	\begin{figure}[H]
		\centering
		\includegraphics[width=0.9\linewidth]{figures/RAID}
		\caption{RAID 0 and RAID 1}
		\label{RAID}
	\end{figure}
\end{minipage}

\subsubsection{Block-level vs. File-level Storage}
\begin{itemize}
	\item \textbf{Block-level:} data is written to and accessed from storage volumes (blocks).
	\item \textbf{File-level:} data is written to disks but accessed through the default file system.
\end{itemize}

\begin{minipage}[c]{0.6\textwidth}
	Virtualization makes the large amount of data center hardware more efficient.
	\begin{itemize}

\section{Types of Virtualization}

\begin{minipage}[c]{0.6\textwidth}
	\subsection{Server Virtualization}
	Multiple VMs are hosted on one physical server, which increases the efficiency of the data center and lets computing resources be delivered to customers using less hardware.
\end{minipage}%
\hfill
\begin{minipage}[r]{0.40\textwidth}
	
	\begin{figure}[H]
		\centering
		\includegraphics[width=0.9\linewidth]{figures/ServerVirtualization}
		\caption{Server virtualization}
		\label{ServerVirtualization}
	\end{figure}
\end{minipage}

\begin{minipage}[c]{0.6\textwidth}
	\subsection{Storage Virtualization}
	The storage capacity is pooled and distributed to the VMs:
	\begin{itemize}
		\item Physical storage devices are partitioned into logical storage units called \textbf{LUNs}.
		\item LUNs are used to create a \textbf{datastore}.
		\item VM disks are stored as \texttt{.vmdk} files and VM settings as \texttt{.vmx} files on the datastore.
	\end{itemize}
\end{minipage}%
\hfill
\begin{minipage}[r]{0.40\textwidth}
	
	\begin{figure}[H]
		\centering
		\includegraphics[width=0.9\linewidth]{figures/StorageVirtualization}
		\caption{Storage virtualization}
		\label{StorageVirtualization}
	\end{figure}
\end{minipage}

\begin{minipage}[c]{0.6\textwidth}
	\subsection{Network Virtualization}
	The physical network components are virtualized to create a \textbf{virtual network}.
	\begin{itemize}
		\item \textbf{vSwitch:} a virtual switch that virtual devices connect to in order to communicate with each other.
		\item \textbf{VLAN:} a virtual LAN segmented into groups of isolated ports, creating different network segments.
	\end{itemize}
\end{minipage}%
\hfill
\begin{minipage}[r]{0.40\textwidth}
	
	\begin{figure}[H]

\subsection{Application and Desktop Virtualization}
\begin{itemize}
	\item \textbf{Application virtualization:} some applications have specific system requirements. \textbf{VMware ThinApp} packages the program together with its requirements as a virtual app and delivers it to the end user.
	\item \textbf{Desktop virtualization:} solves the resource problems of the mobile workforce (workers who need computing without the hardware). \textbf{VMware Horizon} builds the desktop environment from data center resources and delivers it to the end user's device.
\end{itemize}

\section{Cloud Computing}

\begin{minipage}[c]{0.6\textwidth}
	Cloud computing is the delivery of \textbf{shared computing resources} (software and/or data) \textbf{on demand through the Internet}, as a pool of resources that can be rapidly provisioned in an automated way. Its value comes from:
	\begin{itemize}
		\item Economies of scale.
		\item Elasticity: it scales with the needs of the organization.

		\item Easy access for users wherever they are.
